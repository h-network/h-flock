## Two things worth writing down

⚠ **A pasted message is executed** in a CLI-less window. `[message from alice] …`
became `bash: [message: command not found`, which is the correct outcome and not
a fault — with no TUI there is nothing to absorb the keystrokes. **The check is
that the text arrived**, so the script greps the pane rather than reading its
exit status.

⚠ **Two apparent failures were the harness, not the system.** Both used `tail -5`
on a captured pane, which returned the blank lines *below* the prompt rather than
the message above it. Verified by hand before concluding anything — the
distinction between a broken system and a broken test is the whole reason to
look rather than to re-run.

### A 25th check, added because of how build 17 hid

The window-environment drift survived because **each path was individually
correct and individually tested.** Only their *equality* was wrong, and nothing
compared them. So §11 of the check now hires an agent and diffs its environment
against a booted one, agent name normalised.

⚠ **Unit tests could not have caught this and a third one would not either.**
Making `window_env` the single construction site is the fix; comparing the two
paths where they actually run is what stops a fourth path reintroducing it.

Also made the board section idempotent — it took a ticket and never finished it,
so a second run met *"you already have one open task"*. That failure was the
board working exactly as designed, which is the most misleading kind.

## Third pass — build 18, the activity feed

A real claude agent was hired and given work: *list your files, read your
AGENTS.md, report the line count.* Its feed:

```
events: 10   kinds: {input: 1, output: 2, tool: 7}
tools : {Bash: 6, Read: 1}
fields: [agent, cursor, kind, tool, ts, v]
```

The tools match the task — six shell calls and one file read — so the feed
describes what the agent actually did, not what it was asked to do.

| checked | result |
|---|---|
| a working agent produces `tool` events naming the tools | yes, live |
| `GET /activity` before the tailer exists | `200` and an empty list, not `404` |
| an invalid agent name | `404` |
| SSE delivers events while the connection is open | yes, 42 lines |
| **leakage** — paths, command lines, file contents, prompts | **grep clean** |

⚠ **The leakage grep is the check that matters.** This feed is designed to leave
the tenant over HTTP. `fields` above is the whole event: there is no field a tool
argument could occupy, which is a stronger guarantee than filtering one out.

⚠ **A profiled agent could not be tested and that is not a defect.** `sme-2`
carries `profile=work`, so it reads `.claude-work`, which has never been logged
in — `seed_profile_dir` deliberately copies settings, skills and CLAUDE.md but
**not credentials**, because a profile is a separate account. It showed *"Not
logged in · Run /login"*, exactly as designed.

⚠ **`seed-home.sh check` does not know about profile accounts.** It reported all
three CLIs "logged in" while the `work` account was not, because it only looks at
the default paths. The one real finding of this pass.

## Sixth pass — build 22, and a bug it uncovered

| checked | result |
|---|---|
| `seed-home.sh check` before seeding | every account `NEEDS LOGIN` |
| after seeding | `default` logged in on all three; `work` still `NEEDS LOGIN` |
| the classification test, with a new resource added | fails: `classify new Redis resources: ['brandnew.key']` |
| re-hiring a retired name | `presence` reads `idle`, busy tag cleared |
| hiring the same name three times | **1 window, addressable** |

⚠ **Found while testing the re-hire: `StartAgent` created a duplicate window.**
tmux makes a second window with the same name happily and then refuses to resolve
it — `tmux -t hq:<name>` answers *"can't find window"* on an ambiguous target — so
**every delivery to that agent fails silently from then on.** Three windows named
`rehire` existed and none could be reached. Window creation is idempotent by name
now.

⚠ **One check failed and it was the check.** `dave window gone` slept a fixed 4s
after a `StopAgent`; on a busier tenant the kill had not landed. A `StopAgent` is
an envelope — routed, kicked, opened — so it lands when it lands. The check polls
now, and `dave` was verifiably gone from both the windows and the roster when
looked at a moment later.

That is the third fixed-sleep flake today, and the same lesson each time: **wait
for the condition, never for the clock.**

### The exam result

`API.md` claimed a stranger could build against h-flock. Two clients found
**eight gaps between them**, all now applied:

- `blocked` was absent from the presence description entirely
- enrolment idempotency unstated — clients could not know whether to re-enrol
- SSE resume precedence between `?after=` and `Last-Event-ID` unstated
- the activity `kind` vocabulary never enumerated
- board entries may be bare strings
- **no CORS headers, and `EventSource` cannot send the Bearer token** — the pair
  that forces a browser client to ship its own proxy, written down nowhere

⚠ **The lane that wrote `API.md` still hit five holes building against it.** An
author cannot see what they assumed; only building finds omissions.

⚠ **And the clients caught a live watchdog bug.** Exercising the tenant produced
a real credential alert saying agy was *"expiring"* — about a timestamp already
past, for an account that was working. `token.expiry` is agy's **access** token,
which the CLI refreshes itself. Measured across two machines hours apart: the
value moved. agy is `unknown` now, like codex.
